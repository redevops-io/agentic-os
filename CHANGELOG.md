## v0.4.0 (permissions and authorization security release; date set when tagged)

- **Breaking (permissions):** identifiers (app, user, role, tenant, grant subject, resource name, owner/row column, mask column, action) now follow one contract: non-empty, no leading/trailing Unicode `White_Space`, and no control (`Cc`), format (`Cf`), surrogate (`Cs`), unassigned/noncharacter (`Cn`), private-use (`Co`), line/paragraph separator (`Zl`/`Zp`) or bidirectional-control code point anywhere; never case-folded or normalised. The forbidden set is a generated Unicode 17.0.0 table (`agentic_os/identifier_ranges.json`, built by `scripts/generate_identifier_ranges.py`, provenance in `agentic_os/identifier_ranges.provenance.json`, see `docs/IDENTIFIER_CONTRACT.md`). Stored grants whose names break the rule stop applying (like any malformed grant, counted in `status()["malformed"]`) and are never rewritten; a white-space-only `user`/`app` is an invalid principal (only `""` is absent). `agentic-os permissions audit-identifiers` lists them read-only; migrate by removing and re-adding with a corrected name.
- **Breaking (permissions, fail-closed):** an unrecognised value of `AGENTIC_OS_PERMISSIONS` (or the enterprise switches) refuses to start the app; with permissions requested and no gate registered, `Operator.invoke`, `/invoke`, `/agent/run` and the suite server's `/m/<module>/invoke` deny with an actionable message; the older apps' tool bodies share one execution wrapper; the idempotency cache sits inside the authorised scope (a revoked principal gets the denial, a write whose scope changed is refused); the local profile is read like a secret (regular file, owner, mode 0600, no symlink); the enterprise tool table is read only from an installed distribution and can only add denials; `infra.plan` and `infra.drift` are write. An unset `AGENTIC_OS_PERMISSIONS` is no longer silent: the apps log that authorization is not enforced, `AGENTIC_OS_PERMISSIONS=off` is the deliberate standalone mode, the shipped app images set `AGENTIC_OS_REQUIRE_PERMISSIONS_SETTING=1` (they refuse to start on an unset setting; pass `=1` or `=off`), and a reachable bind in an app's `__main__` with nothing set is refused. `docs/PERMISSIONS_MIGRATION.md` section 19 has the rule and the impact table; `docs/TOOL_CLASSIFICATION_INVENTORY.md` is the per-tool classification record; `tests/sweeps/sweep.py` is the reproducible authorization sweep (~86,000 calls).
- **Agent Gateway (error text):** a capability, write port or gateway seam (authorizer, authority, budget, approvals, egress, audit) that raises now returns a short fixed code to the client of the REST adapter, the MCP bridge and `MCPEndpoint` (`capability_error`, `gateway_error`, `duration_exceeded`, `memory_ceiling_unenforceable`, `execution_class_denied`, `contained_failure(rc=N)`), chosen from a fixed list and never copied from the exception message; a failure outside the handler fails closed with `gateway_error`. The exception and traceback go to the `agentic_os.agent_gateway` server log with the request id (control characters escaped), so that log holds the raw exception text by design. Errors a handler declares itself are unchanged. The FastMCP server also sets `mask_error_details`, and a test exercises its Streamable-HTTP transport over a real HTTP server. Builds on #585. See `docs/PERMISSIONS_MIGRATION.md` section 19. `agentic-privacy`'s `POST /intake` and `POST /request` are a registered, tightly constrained public-intake exception (`agentic_os.tool_actions.PUBLIC_INTAKE_ROUTES`): strict schema and size limit, per-client / per-address / global caps with bounded memory, a honeypot, one fixed Postmark operation to one validated mailbox, a verification link built only from `PRIVACY_PUBLIC_URL` (with it unset and a non-loopback host no message is sent), identical responses for any address, 72-hour retention of unverified requests and a masked audit event. `privacy.intake` stays `write` for the Operator, `/invoke` and the console. See `docs/PERMISSIONS_MIGRATION.md` section 30.
- **Permissions (key file):** `agentic-os permissions init` no longer creates `<dir>/.permissions.key` when `PERMISSIONS_KEY` is set (the grants were already sealed with the environment key; the file was an unused second key beside the ciphertext). A key file next to an environment key is warned about once, by path only, and never used. `init` honours `PERMISSIONS_KEY_FILE` and refuses to create a key file under `PERMISSIONS_REQUIRE_KEY=1`. See `docs/PERMISSIONS_MIGRATION.md` section 32.
- **Permissions (feature boundary):** basic permissions are AGPL and need nothing from `context_runtime_enterprise`: `AGENTIC_OS_PERMISSIONS=1` puts the kernel authorizer over each app's trusted tool table with the local `agentic-os permissions init` profile as the principal (never a request header, no admin bypass); with nothing provisioned the apps start restricted and deny with a pointer to `permissions init`. Enterprise SSO / tenant identity / advanced permissioning / permission-aware retrieval and cache requested without the package fail closed with a missing-capability error. Ten more apps (control-tower, document-editor, growth-assistant, guide, infra, outreach-engine, social-autopilot, agentic-crm, lifecycle, support) enforce grants where their routes and operator capabilities execute.

- Sources/RAG: `RagIndexer` could give different (project, source) pairs the same DuckDB index file (`("a_b","c")` and `("a","b_c")`; likewise with `:`), the same in-memory store, and an id such as `../escape` could place an index outside the index directory: retrieval across projects. Stores are now keyed by the exact pair, ordinary ids (lower-case letters, digits, `.`, `-`) keep the historical file name so existing indexes still resolve, every other id (including any with an upper-case letter, because `ACME_b.duckdb` and `acme_b.duckdb` are one file on macOS and Windows) gets a name derived from a digest of the pair (an index built under an upper-case id is rebuilt on its next indexing), the path is checked to be inside the directory, and a missing or non-string id is refused. Whether it was reachable depended on callers validating ids; the retrieval-isolation scenario in the benchmark's runtime-adversarial lane found it.
- Gmail reconciliation: `message_id_for(idempotency_key, domain)` derives the `Message-ID` a caller should put on an outgoing `email.message.send` (`message_id` input, supported by redevops-connectors' Gmail adapter), stable per intended email and not exposing the key. With it the probe identifies the stored message by its own header instead of treating a lookalike as a candidate. The caller must set it: nothing sets it automatically yet.
- Membrane: the contained child no longer gets the parent's import paths as `PYTHONPATH`, which sits ahead of the standard library, so a directory on the parent's path that holds an `operator.py`, `json.py` or `re.py` (an app directory does: Edge Sentinel has an `operator.py`) broke the child before it ran anything. The paths now travel in `MEMBRANE_PATH` and the child inserts them just before `site-packages`: the standard library always wins, project code still beats an installed copy, duplicates are collapsed, and the environment stays scrubbed.
- Edge Sentinel SOC 2 evidence (AVL-BCK-01): `AzurePostgresBackups` collects completed backups from Azure Database for PostgreSQL Flexible Server (a window with none listed is a gap, never a finding or a pass; the `az` runner is limited to the one read-only listing) and `RestoreDrillLog` records the restore drills a person or job performs. Written from a real listing; a failed backup is invisible to this API and the limit is documented.
- Membrane: a sandbox asked for a memory ceiling on a platform that cannot apply one (macOS refuses `RLIMIT_AS`) now refuses by name (`memory_ceiling_unenforceable`) before anything runs, instead of dying in the child with an unexplained `SubprocessError`; it never runs a capability as if the ceiling applied, and a request for no ceiling (`max_memory_mb=0`) still runs. `membrane.memory_ceiling_enforceable()` reports whether the platform can.
- Tests: the ten tests that prove containment are skipped where the ceiling cannot be applied (with the reason) and a Linux-only guard fails if the CI runner stops enforcing it; the suite clears exported OAuth client credentials and the Projects API's cached connector before every test, so a developer's shell no longer changes the connect tests.
- Goal loop and child agents: `GoalLoop(..., children=ChildSpawner)` keeps every active child under a mission's authority key alive (`ChildSpawner.keepalive_tree`, including children spawned while the mission runs and grandchildren) for exactly as long as the loop is driving that mission, and ends them (`ChildSpawner.end_tree`, deepest first, unused allowance returned) when the loop completes or is cancelled. A loop that only waits stops beating, so credentials lapse within one lease period and the same token works again when the loop resumes; a revoked or expired child is never revived. A child that lost its authority while the mission ran is recorded (`LoopChildLost`, `LOOP_CHILD_LOST` on the sentinel feed). Before this, nothing called `keepalive` or `close_tree`: a long mission's children lapsed mid-run and a finished loop left its children active until reaped. Without `children` nothing changes.
- Edge Sentinel SOC 2 evidence pipeline (ES-5): `soc2/pipeline.py` (scheduled, idempotent, signed collection; a failed collection leaves a gap and no evidence), `soc2/sources/github.py` (change records for SEC-CHG-01, organisation MFA status as the new `mfa_status` kind for SEC-ACC-01, whose control version is now 2) and `soc2/sources/heartbeat.py` (monitor liveness for SEC-MON-01). Written from the GitHub REST documentation and tested against a fake; not run against a live organisation.
- Edge Sentinel SOC 2: a scanner result whose producer states `population_complete: false` is no longer assessed as a PASS (SEC-CFG-01 ignored the flag, unlike the other procedures); it is INCONCLUSIVE. Found by the new SOC 2 assessment-accuracy lane in multiagent-orchestration-benchmark. A scan result that omits the flag is assessed as before.
- Reconciliation probes for Gmail (`email.message.send`), Postiz (`content.publish`) and Apollo (`outreach.enroll`), on a shared `probe_adapters/_common` base; `ProbeRegistry.register(..., ref_derive=...)` derives scalar `effect_ref` fields (a content digest, a joined id list). A record that merely has the same fields (a message to the recipient with the subject, a post with the text) is a candidate: inconclusive by default, `accept_unique_match=True` to opt in. A Gmail `Message-ID` the sender set is verified on the stored message and does identify it. Apollo is confirmed by a membership that began since the call; `contact.upsert`, `outreach.sequence.configure` and `outreach.sequence.activate` are unsupported. Probe transports are GET-only and refuse any other path.
- Lago refund probe: a single credit note matching invoice and amount is no longer treated as proof the refund executed (an unrelated refund looks identical); it is reported inconclusive with the candidate named for a person to confirm. `accept_unique_refund_match=True` restores the old behaviour for deployments where nothing else can refund the same invoice and amount.
- Reconciliation: a reservation now records `effect_ref`, the few input fields that identify the effect at the provider (declared per capability, never secrets), so a read-only probe can look the effect up. First adapter: Lago (`mission/probe_adapters/lago.py`): subscription create/cancel by `external_id`, refunds by invoice + amount since the call. Lago has no idempotency lookup and no documented visibility window, so no Lago probe can prove non-execution; a missing record is `INCONCLUSIVE` and escalates. Payment retry is `UNSUPPORTED`.
- Edge Sentinel SOC 2 readiness foundation (`apps/edge-sentinel/soc2/`): a durable, signed, append-only, hash-chained, tenant-scoped evidence vault; an 11-control catalog with AICPA criterion references; an assessment engine where missing, partial, unverifiable or merely claimed evidence can never be a PASS; an append-only ledger with separation of duties and expiring exceptions; restricted and counts-only benchmark exports that cannot carry a certification claim. Readiness evidence for a reviewer, not an attestation.
- Gateway: a side-effecting direct call whose earlier attempt has an unknown outcome is no longer sent again. It is refused (`authority:outcome_unknown`, visible to `on_authority`) until `AgentGateway.reconcile_call` resolves it with evidence and a named person (executed: a retry gets the recorded result; not executed: the reservation returns); `unresolved_calls(key)` lists them. In the production profile a side-effecting direct call without an idempotency key is refused. Found by running a real agent loop (agent-harness, context-runtime) against the gateway with a model that retries immediately after a timeout.
- Projects API (F22): all 19 write routes have an authorization policy and the app installs the route-authorization layer; in the production profile an unauthenticated or unclassified write is refused before any handler runs, human decisions (approve, reconcile, batch, connect app, confirm sources, policy promotion, simulated outcome) are human-only, and the demo is unchanged outside production. Fixes the layer for an app mounted under a base path (it matched the full path and refused or skipped everything). The pinned unauthenticated-routes list shrinks from 19 to 5.
- Context integrity (`mission/context_integrity.py`): the owner's scope is pinned (first message, byte-identical, never summarized; a missing, edited or planted copy is repaired and reported), messages carry provenance with only owner/system trusted and unlabelled treated as untrusted, summaries of untrusted content are fenced and never given the system role, compaction fails closed, and each compaction leaves an audit record. Sentinel feed (`mission/sentinel.py`): one canonical, deduplicated, durable, cursor-pulled stream of goal-loop, child-agent, reconciliation, context, egress and assurance events. Edge Sentinel consumes it (`apps/edge-sentinel/agent_events.py`): events become AI_SECURITY cases that are signals, never actions or closures.
- Docs: moat and competitive-advantage framing removed (the intelligence layer description, the gateway plan's messaging section, 'moat plan' references in docstrings, `examples/intelligence_moat_demo.py` -> `intelligence_demo.py`); one file-naming convention per folder (`docs/` is UPPER_SNAKE like its majority, `audit/` is lower-case like its majority): `docs/ARCHITECTURE.md`, `INTELLIGENCE.md`, `MISSION_EXECUTION.md`, `SECURITY_MODEL.md`, `audit/autonomy-authority-audit.md`.
- Child credentials now live as long as the mission runs: one token for the whole mission (expiring only with the child's envelope) whose short life is a liveness lease extended by the owner's heartbeat (`ChildSpawner.keepalive` / `heartbeat`), not by the token's own use; a lapse is recoverable with the same token, close/revoke/revoked ancestor/envelope expiry are final; `reap_lapsed` closes abandoned children and returns their allowance. Replaces the fixed 15-minute credential lifetime.
- Child-agent identities and scoped credentials (`mission/children.py`): a spawned worker gets its own principal, an attenuated envelope, an allowance carved out of the parent's counters (unused part returns on close), a durable registry with per-parent and per-tree active caps, and a signed, short-lived, client-bindable, instantly revocable credential. `AuthorityGuard` now walks the delegation chain at every decision (revoking, expiring or narrowing an ancestor stops all descendants; a child with no stored parent is denied); the gateway (`child_credentials`, `GatewayRequest.credential`) takes a child's envelope only from a verified credential and records the agent in the reservation. Envelopes without a parent serialise and digest exactly as before.
- Goal-loop controller (`mission/goal_loop.py`): pursue a goal across iterations (each an ordinary mission) with hard ceilings that stop it (iterations, active time, usd, tokens, deadline; raised only by a named owner), soft progress thresholds that diagnose, replan a bounded number of times and then escalate instead of terminating, completion only by an independent verifier with evidence, no new iteration or replan while any unknown outcome is unresolved, immediate escalation for authority denials and mission ceilings, fenced leases for the loop and each mission, durable checkpoint/resume, cancellation that lists what may remain, `classify_loop` and `Wait.STALLED`. The serial runtime now stops dispatching once a mission is cancelled.
- Fork reconciliation parity: a fork branch whose call may have been sent but whose outcome is unknown now follows the plan-node contract (a `ReconciliationRequired` record, the reservation stays UNKNOWN, the fork parks the mission in `WAITING_RECONCILIATION` and returns `awaiting_reconciliation`, nothing is resent, a failing join waits instead of compensating around it) and is resolved through `reconcile_node` / the supervisor, after which the same fork continues. A restarted fork reads each in-flight branch's reservation: never-sent branches are sent, side-effecting dispatched ones park, read-only ones re-run, and a success recorded before the ledger settled is settled from the log. Tested by a crash-and-restart of three branches (succeeded / unknown / running) in the production profile.
- Reconciliation supervisor: structured probe results with provider qualifications (a negative is accepted only from a qualified adapter, past its visibility window; a 404 is never one), a durable bounded retry scheduler (backoff, Retry-After, restart-safe budgets, compare-and-swap claims, exactly-once escalation with a stable notification key), mission ownership leases with fencing enforced inside the append, independent branches continuing while one node awaits reconciliation, and wait-state classification so a waiting mission is never treated as stalled. No provider adapters ship yet. See `docs/MISSION_EXECUTION.md`.
- Unknown outcomes park instead of failing (`WAITING_RECONCILIATION`): a dispatched node whose outcome is unknown parks the mission durably (survives restarts; `run()` is a no-op while parked), `POST /missions/{id}/reconcile` resolves it with evidence (approver/admin credential only, actor from the credential), and the SAME mission resumes without rerunning completed work. At-most-once dispatch from #553 is unchanged. Fork branches keep their own semantics; provider probes, periodic reconciliation and notifications are the supervisor's.
- Hard limits and reconciliation: the serial mission loop enforces `deadline`, `wall_clock_s`, `usd` and `tokens` (`HardLimitReached`); reservations carry a durable record (mission, node, attempt, idempotency key, provider reference); `mission/reconcile.py` settles or releases a reservation only when an independent probe proves the outcome (otherwise it stays counted and is flagged), with a manual resolution CLI; the runtime refuses to dispatch a reservation that was already dispatched, in every profile. No provider probes ship yet.
- Network egress boundary (F10): `deploy/egress/` (allowlist forward proxy with an SSRF guard and a JSON decision log, inbound forwarder, self-test), optional `deploy/apps/compose.egress.yml` overlay that puts the apps stack on an internal network behind the proxy, `deploy/k8s/networkpolicy-egress.yaml`, and `--require-egress` / `egress_proxy_configured` in the production preflight. Opt-in; the default install is unchanged. See `deploy/egress/README.md` for guarantees and limits.
- Route authorization (F20/F21): one enforcement layer (`agentic_os/app_kit/route_authz.py`) and a policy for every write route of the 17 apps (human / agent / service contexts, access classes, production refuses unauthorised and unclassified writes before the handler runs); `approval_required` enforced on every operator `/invoke` in every profile (`AGENTIC_OS_ALLOW_UNAPPROVED_INVOKE=1` is a non-production testing override); CI gates for unclassified routes and unreviewed entry points; kernel unauthenticated write routes inventoried and pinned (F22: the Projects API is a demo surface and must not face a real runtime unauthenticated).
- Operator authority boundary (F19): in the production profile an operator's `/invoke` refuses a side-effecting call that has neither a human approval nor an execution authorization issued after the envelope and policy were evaluated; authorizations are signed, single-use, bound to the exact call and replay-protected across replicas; mission identity comes from signed claims; direct-action flow `POST /actions/authorize`; `AGENTIC_OS_PROFILE` diagnostics in `/health`, operator `/_security` and `python -m agentic_os.mission.profile --require-production`. Known gaps: apps' own REST routes (F20). See `docs/SECURITY_MODEL.md`.
- Authority as an invariant: `AGENTIC_OS_PROFILE=production|development|test` (production requires a durable guard in `MissionRuntime`, `AgentGateway`, `Fleet` and checks every node against the owner's envelope); serial nodes and fork branches share one gate; reservation lifecycle RESERVED/DISPATCHED/SETTLED/RELEASED/UNKNOWN with atomic, idempotent transitions; Fleet agent work and background jobs are inside the envelope. Known gap: operator `/invoke` direct calls (audit F19).
- Standing grants: `PolicyRule.approval_mode = standing_grant_satisfies` lets an explicit `mission-authority/v1` grant stand in for an ordinary approval gate (never DENY, never a mandatory approval, never beyond its limits); durable `SqliteEnvelopeStore`; `AGENTIC_OS_REQUIRE_AUTHORITY` / `AGENTIC_OS_AUTHORITY_DB`. Existing policy digests unchanged.
- `mission-authority/v1` (`agentic_os/mission/authority.py`) and `AgentGateway(authority=...)`: durable-envelope-style authority with resource/limit/expiry/revocation/attenuation, fail-closed at the gateway, delegated missions inherit the owner's constraints. See `audit/autonomy-authority-audit.md`.

## v0.3.43 (security and execution-correctness release)

Merged in #510-#521 (audit reports in `audit/`):
- Live publishes need an authenticated, authorised approver (tenant, channel and grant scope); the actor comes from the credential.
- An ambiguous send is UNKNOWN and reconciled (authoritative lookup or an authorised manual statement) before any retry; provider success claims need an independent probe on real adapters; the idempotency key now reaches the provider.
- Gateway approvals are single-use, expiring, atomic and cannot be self-approved; mission approvals are bound to the inputs the approver saw.
- Durable replay guard (`AGENTIC_OS_REPLAY_DB`; `AGENTIC_OS_REQUIRE_DURABLE_REPLAY=1` refuses to start without it).
- Per-mission hash-chained event log (JSONL and in-memory stores only), assurance sensors, optional approval TTL (`AGENTIC_OS_APPROVAL_TTL_S`).
- KeePassXC secret store; LLM key and provider resolved per call through the broker, changeable at runtime with test and rollback.
- Honest dunning status, Guide wording, fiscal-year close warning; third-party images in `deploy/apps` pinned by digest.
- Production settings to enable: `AGENTIC_OS_REPLAY_DB` + `AGENTIC_OS_REQUIRE_DURABLE_REPLAY=1`, tenant `content.publish` grants, `AGENTIC_OS_APPROVAL_TTL_S`.
