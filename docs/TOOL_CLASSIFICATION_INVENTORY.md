# Tool classification inventory

The inventory behind `agentic_os/tool_actions.py` (generated by `scripts/generate_tool_inventory.py`; a test fails when a tool has no row or a row disagrees with the registry). One row per tool. **Classification is not enforcement:** the gate enforces the action recorded here, and a static scan cannot prove a tool read-only. `tests/test_read_classification_sinks.py` is a regression signal only (it cannot see indirect execution, imported helpers, or a subprocess behind an injected runner). A tool whose behaviour is selected by the caller's input (a mode flag, a playbook, target or vars argument, a scan with options) is classified at the strictest action it can perform unless it is split into separate tools. Authorisation (this table) and approval (the last column) are separate checks.

Categories: `read-only-state` (reads state, writes nothing observable) / `writes-local-or-persistent-artifacts` (files, assets, records it owns) / `launches external process or network` (a scanner, a deploy, a provider or CRM/e-mail/payment call, an editor service) / `dynamically selected behaviour` (the caller chooses what runs) / `public intake: unauthenticated by design` (the tool is `write` for the Operator, `/invoke` and the console, and a route registered in `PUBLIC_INTAKE_ROUTES` may ALSO call it with no grant, to open a PENDING request only; see `docs/PERMISSIONS_MIGRATION.md` section 30).
