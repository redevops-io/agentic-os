### 2.3 Portability flags (what was searched and found)
Searched `src/redevops_rag/*.py` for fcntl, resource, fork, /proc, /tmp, signal, symlink, chmod, bash, subprocess, expanduser, HF_HOME: no hits. Findings:
1. Path-derived identity. `did = str(f)` is the document id and part of the content-addressed chunk id (`ingest.py:87`, `chunk_identity(did, t)` at `ingest.py:98`); prune compares `str(f)` strings (`ingest.py:117`). INFERRED: on Windows ids contain backslashes and drive-letter case; on case-insensitive filesystems the same file can appear under two spellings; an index built on one OS is not id-compatible with the same corpus indexed on another. Fix: normalise to a root-relative POSIX path plus a stable root key.
2. Silent FTS degradation. `_load_fts()` catches every exception and returns False (`store.py:60-65`). With no network on first run, BM25 is silently absent and results come from vector-only retrieval. Confirmed offline in a throwaway DuckDB with a dead extension repository: `IO Error: Failed to download extension "fts"`. A native install needs the extension preinstalled or bundled, or a hard failure.
3. Text I/O without encoding in the citation-graph cache: `open(cpath)` and `open(cpath, "w")` (`citation_graph.py:328,338`) use the locale code page on Windows (cp1252), so non-ASCII cache entries can fail to round-trip. `ingest` reads with explicit utf-8 (`ingest.py`).
4. Symlink semantics: `iter_files` refuses links that resolve outside the root (`ingest.py:20-33`). Windows symlinks and junctions behave differently and creating them needs privilege; INFERRED the check still works via `resolve()` but is untested on Windows.
5. Model cache on Windows: Hugging Face cache uses symlinks and falls back to copies without Developer Mode (known behaviour, UNVERIFIED here); disk use doubles.
6. No Windows or macOS CI: `.github/workflows/tests.yml` runs `ubuntu-latest` only, installs `.[pg]`, `[rerank]` not exercised.

### 4.4 Supervisor, egress and path policy on Windows and macOS (static reading plus runs)

macOS arm64 (observed, this audit): `packages/qa-adapter-kit/tests` 359 passed, `qa-robot` offline 133 passed, `qa-robot` real Robot Framework 7.5 10 passed, using the source tree on `PYTHONPATH` in a throwaway venv (not the exact install-profile steps, which install non-editable wheels). This reproduces the owner's earlier macOS result of 359 + 133 + 10. Other earlier results given by the owner (Ubuntu 24.04 non-root pass except the test fixed in #26; running as root under `/root` fails with `PROHIBITED_PATH`) were not re-run; the root failure is explained by code: `"/root"` is in `DENIED_PREFIXES` (`paths.py:16`) so any workspace or temp root under `/root` is refused (`PathPolicy.__init__` at `paths.py:37`).

Behaviours worth recording on macOS (run here with the real functions):
- `is_denied("/ETC/passwd")`, `is_denied("/Users/x/.SSH/id")` and `is_denied("/PRIVATE/ETC/hosts")` return False (case-sensitive comparison); `is_denied` is applied to both the raw and the `realpath` form (`paths.py:53`), and on this APFS volume `realpath('/ETC/hosts')` resolved to `/private/etc/hosts`, so `/etc` is still caught via the real path. A directory that is not a symlink (for example `.SSH` spelled in upper case) keeps its typed case under `realpath`, so the credential-component deny-list can be bypassed on case-insensitive volumes (default macOS and Windows) if a credential directory is inside an allowed root. The deny-list is documented as a safeguard against a mistaken root, not the primary control, so this is a defence-in-depth gap, not a demonstrated exploit.
- Scratch/home directory is `tempfile.mkdtemp` (`runner.py:105`), which on macOS is under `/var/folders/...` (real path `/private/var/folders/...`); `/private/var/run` is denied but `/private/var/folders` is not, so the default works.

Windows (INFERRED from code, no Windows run):
1. Process groups and signals: `start_new_session=True` is POSIX-only (ignored on Windows), `os.killpg` does not exist on Windows (`supervisor.py:166`), and `signal.SIGKILL` does not exist (`:226,231`). First deadline/cancel/output-limit event would raise `AttributeError` inside the supervisor. The README states "POSIX only (process groups)" (`qa-adapter-kit/README.md:50`). Needed: Job Object-based tree kill (or `CREATE_NEW_PROCESS_GROUP` plus `TerminateJobObject`), exit-status mapping without POSIX signals.
2. Environment: child env is rebuilt from nothing with `PATH=/usr/bin:/bin`, `HOME`, `TMPDIR`, `LANG=C.UTF-8` (`supervisor.py:139`) and `PATH|HOME|TMPDIR` are forbidden names (`:40`). Windows children usually need `SystemRoot`, `TEMP`/`TMP`, `USERPROFILE`/`APPDATA`, `PATH` entries; a Python child without `SystemRoot` commonly fails to initialise (UNVERIFIED here). Needs a per-OS base-environment table.
3. Path policy: deny-list prefixes are POSIX (`paths.py:16`) and matched with a `"/"` separator after `os.path.normpath` (`:23`), so on Windows (backslash-normalised) no prefix ever matches; Windows credential locations (`%APPDATA%`, `%USERPROFILE%\.ssh`, Credential Manager files, `C:\Windows`) are not listed; the root check `real == Path("/")` (`:37`) does not catch drive roots; the argument check only inspects arguments starting with `/` (`supervisor.py:98`). Case-insensitivity, 8.3 short names, UNC paths and junctions need explicit handling.
4. Executable allowlist compares `os.path.realpath` (`:103,108`); `.exe`/`.cmd` resolution, `PATHEXT`, and case-insensitive compare are not handled; container-engine and downloader name lists are bare names (`docker`, `pip`) and would miss `docker.exe`/`pip.exe` unless suffixes are stripped (`:34-36,104-115`).
5. Other POSIX-only code: `os.getuid()` in `qa-checks/.../seed_copy.py:344,357,363` (AttributeError on Windows); `tests/test_environment_preflight.py` requires `HOME` to be under a POSIX temp root; the install profiles and `tools/check_install_profiles.py:40` use `bin/python`.
6. Egress: the gateway is stdlib asyncio and has no OS-specific code found by grep (only `signal.SIGINT/SIGTERM` handlers in `qa_egress/__main__.py:38`, where `add_signal_handler`-style code can differ on Windows). Its enforcement premise ("the browser's network has no other route than this gateway") is a deployment property; on native Windows and macOS hosts there is no namespace to enforce it. INFERRED: for native tests the gateway is a policy decision point for clients that opt in, not containment.
7. Antivirus and quarantine: sealed runs execute pinned interpreters and test binaries from temp directories; real-time scanning, SmartScreen and Gatekeeper/quarantine can add latency or block unsigned test binaries (UNVERIFIED, platform behaviour not exercised).

macOS-specific static risks: keychain access prompts for unsigned rebuilt binaries (documented in `agentic-os/deploy/launcher/DESKTOP.md`); TCC permissions for any UI automation.

## 5. Host / runner topology recommendation

Facts (GitHub docs, fetched 2026-11-01, https://docs.github.com/en/actions/reference/runners/github-hosted-runners): standard GitHub-hosted runners are "free and unlimited on public repositories". Labels: Windows x64 `windows-latest`, `windows-2025`, `windows-2022` (public: 4 vCPU / 16 GB / 14 GB disk); macOS arm64 `macos-latest`, `macos-14`, `macos-15`, `macos-26` (3 vCPU / 7 GB / 14 GB); macOS Intel `macos-15-intel`, `macos-26-intel`; Windows arm64 `windows-11-arm`. All four repos in scope are public, so hosted Windows/macOS minutes are not a cost. Hosted macOS arm64 runners are the CI path for the Apple Silicon target; no Apple hardware is needed for CI.

Self-hosted: GitHub's own guidance (https://docs.github.com/en/actions/reference/security/secure-use) is that self-hosted runners "should almost never be used for public repositories" because any user can open a pull request and compromise the environment; if used, ephemeral JIT runners with a clean environment per job.

Recommendation:
1. Per-OS test lanes on hosted runners: `windows-2022` and `windows-2025` (x64) and `macos-14` plus `macos-15` (arm64). Start with `macos-14` and `windows-2025` as required; add the sibling images as non-required to detect image drift.
2. Phase the lanes: first Engine B/E offline suites (pytest, verifier, deterministic digests) which need no supervisor port; then the supervisor Windows port gated by its own unit tests; then Engine A lifecycle tests; Engine C on loopback; Engine D last.
3. Use a Windows 11 test machine only as a manual or ephemeral validation box (clean-install/uninstall, SmartScreen/Defender behaviour with signed builds), not as a runner attached to public repositories. It was not touched in this audit.
