## B2 - HMAC approval token: PRESENT in Go
- go/mission/approval.go:1-237 (== kernel go/mission/approval.go, `diff` identical). Mint L97-110 binds operator, capability, mission_id, node_id (blank -> null via normID), inputs_sha256, marker, exp, nonce (16 random bytes hex). Verify L121-171: HMAC compare, exp > now, operator/capability equality, `bindingOK` fail-closed (bound dim needs non-empty equal presented value; null = unbound), inputs hash via hmac.Equal, marker must be object, ReplayGuard.Consume AFTER all other checks (same order as Python). ReplayGuard L186-236: bounded, fails closed when full, prunes expired; per-process (same caveat as Python SharedStore seam).
- Python ref: agentic_os/mission/approval.py (mint ~L100, verify ~L113, ReplayGuard).
- Deliberate difference: no platform secrets-file fallback in Go (env AGENTIC_OS_APPROVAL_SECRET only) -> a Python deployment that uses the secrets file will mint tokens Go cannot verify (fail closed, but a config trap).
- Number handling: Go re-encodes inputs through json UseNumber (normalizeNumbers) so 10 vs 10.0 hash as on the wire; Python hashes its in-memory value. Equivalent only if both sides hash the post-wire value; verified by tests `TestInputsHashUsesTheWireForm`, `TestPythonMintedTokenWithIntegerInputsVerifiesOnGoOperator`.
- Canonical here is `json.dumps(sort_keys, separators=(",",":"), default=str)` with ensure_ascii=TRUE (default). Go pyjson.go `writePyString` escapes non-ASCII incl. 0x7f and astral surrogate pairs -> matches. (Note: this is the OPPOSITE of B4 which is ensure_ascii=False.)
- Covering tests: go/mission/approval_parity_test.go (TestApprovalTokenMintIsByteIdenticalToPython L102, VerifyMatchesPython L126, SingleUseLikePython L149, ForgedTokenUnderEmptyKeyIsRejected L332, ReplayGuardFailsClosedWhenFull L351, CanonicalNonFiniteMatchesPython L245), fixtures go/mission/testdata/approval_tokens.json (generated from Python), go/service/approval_e2e_test.go (TestHTTPApprovalDeliversSignedTokenToOperator), approval_marker_test.go.
- NOT covered: unicode/astral/DEL strings, big ints, exp as float vs int in vectors (see recommended vectors).
- .NET: nothing. Ent. Python: nothing re-implemented; relies on kernel.

## B4 - hash-chained per-mission event log: ABSENT in Go and .NET; BROKEN in enterprise Python
- Python ref: agentic_os/mission/store.py:69-110: `sha256(prev.encode("ascii") + b"|" + json.dumps({seq,ts,type,mission_id,payload}, sort_keys=True, separators=(",",":"), ensure_ascii=False, default=str).encode("utf-8"))`; prev per mission; "" for first; verify_chain tolerates unchained legacy events.
- Go: grep for hash/prev/chain in go/mission/store.go (and kernel go/mission/{store,events}.go) finds nothing. go/events/events.go is the v10 RuntimeEvent contract: event_id = "ev-"+sha256("|"-joined fields + encoding/json payload)[:16] - content-addressing, NOT a chain, and uses Go json.Marshal (HTML-escapes <,>,& as <; sorts map keys; NOT Python-compatible). go/canonical = rcv1 (NFC normalise, drop nulls, refuse floats, ints as IntLit, "rcv1:" prefix) - a different canonicalisation, deliberately not the store's. go/identity AccessLedger and go/sandbox ProvenanceLedger ARE hash chains (identity.go:253-400, genesis 64 zeros, v2 digest = rcv1) but are access/provenance ledgers, not mission event logs.
- Can go/events or go/canonical produce the store's canonical JSON? No: (1) canonical NFC-normalises strings and drops nulls (store does neither); (2) it rejects floats (store has float `ts` and float payload values); (3) events.go uses encoding/json. The closest reusable piece is mission/pyjson.go `writePyJSONSep` (exact Python separators, pyFloat repr, UseNumber ints verbatim) but its string writer is ensure_ascii=TRUE, so a Go chain needs an ensure_ascii=False string writer (emit raw UTF-8, escape only `"` `\` and C0 controls; Python also leaves U+007F, U+2028/9 raw when ensure_ascii=False).
- Enterprise Python: agentic_os_enterprise/mission/store.py `Event` has no prev/hash, JSONL writer uses plain json.dumps (ensure_ascii=True, unsorted). PROBE (kernel venv): `agentic_os.mission.store.verify_chain(agentic_os_enterprise EventStore().all())` -> `AttributeError: 'Event' object has no attribute 'hash'`. Kernel receipt.py:40 and assurance.py:49 call verify_chain on `rt.store`, so any enterprise-constructed runtime that is handed the enterprise store loses (or crashes on) receipts/assurance. 15 enterprise files import the forked EventStore. tests/test_eventstore_conformance.py compares enterprise Memory vs Jsonl only, never the chain.
- Cross-language risks if a chain is ported: (a) ensure_ascii=False vs True; (b) float `ts`: Python repr (1e+16, 1e-07, 10.0 keeps ".0", -0.0) vs Go/C# shortest formats - pyFloat in pyjson.go handles it, C# `double.ToString("R")` does not (1E+16, "10"); (c) int vs float distinction through any JSON round-trip (10 vs 10.0; decode with UseNumber / BigInteger; Python ints are arbitrary precision); (d) key order: Python sorts by code point, Go sort.Strings by UTF-8 bytes (equal except astral vs BMP>U+D7FF: UTF-16 ordinal order in C# `StringComparer.Ordinal` DIFFERS from code-point order for astral keys; ControlPlaneWire.cs uses Ordinal -> latent bug for non-BMP keys); (e) NaN/Infinity bare tokens (Python allows; Go refuses - nonfinite.go placeholders); (f) `default=str` fallbacks (datetime, enums, Path, set) - Python stringifies, other languages cannot reproduce; (g) NFC: do NOT normalise (rcv1 does; store does not); (h) lone surrogates / invalid UTF-8; (i) payload dict key types (int keys become strings in Python json but sort before conversion -> sorted by original type; mixed keys raise); (j) `prev` joined with "|" as ASCII; (k) HTML-escaping in encoding/json; (l) truncation of log end undetectable (ledger_head anchoring needed).
- .NET: nothing. ControlPlaneWire.Esc escapes only \\ " \n \r \t and <0x20 as \u00xx - Python json.dumps writes \b and \f as short escapes (\b \f), C# emits \u0008/\u000c (mismatch), and non-ASCII raw (that matches ensure_ascii=False but not the approval canonical). Test vectors only cover ASCII.

## Top risks
1. Per-mission hash chain exists only in the kernel Python; the Go ports, .NET and the enterprise Python store lack it, and the enterprise store is not merely missing it: kernel verify_chain/receipt/assurance raise AttributeError on enterprise Events (probe-confirmed). Any enterprise runtime given the forked store loses tamper evidence or crashes receipts.
2. Fork drift: enterprise go/mission differs from kernel go/mission in ~10 files and lacks events/fork/concurrency; enterprise Python mission/{store,executor,planner,templates,...} are forks beyond the thin runtime subclass; parity is only enforced where vectors exist (approval, policy, compensation, result classification). Go tests unrun here (no toolchain).
3. Missing/untested cross-language edges: .NET encoder (UTF-16 Ordinal key sort, \b/\f escapes, double formatting) will diverge from Python for non-ASCII/astral/float data; approval secret-file fallback absent in Go; B13 reconcile, B12 inbox, B11 grant/live-publisher, B10 stores, tenant_limits have no Go/.NET equivalent.
